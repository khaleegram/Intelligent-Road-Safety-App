 2.1 Define the MVP in ONE sentence (anchor)
> MVP Goal:
> A mobile app that lets users view accident hotspots on a map, submit accident data, and receive basic warnings when a selected route passes near known high-risk locations.
If a feature does not support this sentence, it does not belong in MVP.
 2.2 MVP Feature List (locked)
These are non-negotiable MVP features. Nothing more, nothing less.
 A. Core User Features
1. View accident hotspots on a map
2. Submit accident reports
3. Select a route and receive hotspot warnings
4. Use the app with limited functionality offline
 B. Technical Features
1. Cloud data storage (Firebase)
2. Map visualization (Mapbox)
3. Rule-based hotspot logic (temporary)
4. Local caching + sync queue
5. Simple settings screen
 2.3 Explicitly OUT of scope for MVP (write this down)
This protects you.
❌ Real-time accident detection
❌ Emergency dispatch
❌ Advanced offline navigation
❌ Automatic ML retraining
❌ Multiple user roles
❌ Admin dashboard
❌ Full multilingual support
❌ Advanced analytics
These go to Phase 2+, not “maybe later”.
 2.4 Break MVP into Modules (this is the real work)
You are not building “an app”.
You are building modules.
 Module 1: App Foundation
 Expo project setup
 Navigation structure
 Global state
 Environment config
Deliverable: App launches, navigates, does nothing useful yet.
 Module 2: Data Layer
 Firebase project
 Firestore collections
 Write / read rules
 Network error handling
Deliverable: Data can be saved and fetched reliably.
 Module 3: Accident Reporting
 Accident form UI
 Location picker (map tap)
 Validation
 Submit → Firestore
Deliverable: Accident appears in database with correct fields.
 Module 4: Hotspot Logic (Rule-Based)
This replaces ML temporarily.
Logic example:
```
Group accidents by grid cell
Count accidents per cell
If count > threshold → hotspot
```
Deliverable: You can compute hotspots without ML.
 Module 5: Map Visualization
 Display user location
 Render accident markers
 Render hotspots (color-coded)
 Tap hotspot → details
Deliverable: Client can visually understand risk areas.
 Module 6: Route & Warning System
 Destination input
 Route rendering
 Distance check between route and hotspots
 Warning UI (banner / modal)
Deliverable: User sees warnings before entering risky zones.
 Module 7: Offline Support
 Cache hotspot data locally
 Queue accident submissions
 Sync on reconnect
Deliverable: App does not break without internet.
 Module 8: Basic Settings
 Language toggle (English only for now)
 Cache refresh
 About screen
Deliverable: App feels complete, not hacked together.
 2.5 Define the Data Contracts (critical)
If you don’t define this now, ML will punish you later.
 Accident Record
```
id
latitude
longitude
timestamp
severity
road_type
weather
vehicle_count
casualty_count
created_at
```
 Hotspot Record (computed)
```
area_id
center_lat
center_lng
risk_score
severity_level
accident_count
last_updated
```
This structure must not change without good reason.
